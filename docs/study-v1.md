# Flashcard decks and study policies v1

Decks use schemaVersion 1.0.0 and a stable lowercase UUIDv4. Card IDs are unique within a deck and contain an initial ASCII letter plus at most 63 letters/digits/dot/underscore/hyphen. Reuse IDs when translating content; changing an ID identifies a different card. Decks contain zero through 1,000 cards. Empty decks are valid: position is null, no study action is accepted, and evaluation remains unevaluable/unassessed without a score.

Front, back and optional hints are validated ContentNode values. Tags are unique strings (up to 20, at most 64 characters each). Optional card/deck metadata contains a shared LocalizedText title and optional ContentNode description. Objects are closed; duplicate IDs, unsupported content and invalid localized/shared values are rejected. Deck JSON is bounded to 2 MiB, depth 32, 50,000 nodes and collections of 1,000 to compose with Core.

createStudyPorts captures validated copied deck/policy data and returns pure Core StatePorts. initialState checks that the ActivitySpec is a flashcards activity with exactly the captured deck config. Actions use Protocol names interactive-project/flashcards.reveal, next, previous, skip and rate. Unknown/malformed/disallowed actions return accepted=false, so Core leaves state/revision/events unchanged. Every accepted domain transition produces immutable state through Core. Live clocks/services and UI input mechanisms remain outside deck/state.

Reveal exposes the current back once per visit. Repeated reveal is rejected. Moving next/previous or skipping resets revealed=false; out-of-range navigation is rejected. Rating requires reveal except in exam-like mode and is accepted once per card per study session. Skip records the current card once and advances when possible; skipping the final card stays at the last position without wrapping. Revisiting a reviewed card does not duplicate a rating.

Ordered mode preserves deck order and permits forward/back navigation. Seeded-random mode uses an explicit uint32 seed and mulberry32-fisher-yates-v1 to capture a reproducible permutation; it never calls Math.random or the host random port. Guided mode accepts an explicit complete unique permutation, permits forward movement after review/skip, and forbids previous. Exam-like mode preserves order, forbids reveal/hints/previous/skip and requires a self-rating before next. It is an interaction policy, not a secure examination system: the practice deck contains back content.

again/hard/good/easy map to normalized self-reported confidence 0,1/3,2/3,1. Outcomes explicitly carry kind=self-report and correctness=null. A rating is independent of mouse/swipe/keyboard/voice and never claims objective correctness, learner score or a scheduling due date. Timestamp comes only from Core's injected clock. Aggregate Protocol evaluation is unevaluable/unassessed for every policy.

No repetition algorithm, memory model, remote service, renderer, CSS, keyboard binding or hidden answer transport is implemented here. Hosts display front/back/hints according to state/policy; exam-like interaction must not be represented as answer secrecy. Versioned session snapshots and review/event/privacy policy are handled in flashcards#2; scheduling adapters remain separate packages.

Fixtures contain en/es/ar text and composed math/image/code/reference content, duplicate/unsupported decks, a valid empty deck and a pinned seeded-order golden fixture. Tests run the actual Core runtime for action constraints, immutable reviews, all policies, empty/out-of-range behavior and repeated reveal, with TypeScript consumers.
